# Платный трафик без заказов: разбор 19–21.08.2026

С 19.08.2026 на магазин пошла платная реклама Instagram/Facebook — вместо 1–6
посетителей в сутки стало ~170. Заказов при этом не было ни одного с 14.08,
регистраций — с 12.08. Ниже разбор: что измерили, где ошиблись, что нашли.

## 1. Воронка по логам nginx

Считалось по `/var/log/nginx/access.log*`. Формат `combined`, домен в логе не
пишется, поэтому магазин отделялся по utm-заходу и `Referer`. Отсеяны боты по
User-Agent и собственный адрес сервера `86.107.45.211`.

| шаг | 19.08 | 20.08 |
|---|---|---|
| клик по объявлению, страница открылась (200) | 155 | 186 |
| браузер получил список товаров (`/Product/GetProducts` 200) | 130 | 159 |
| отрисовался первый экран (≥1 карточка) | 111 | 136 |
| **пролистал дальше первого экрана** | **6** | **4** |
| нажал «В корзину» (`POST /Cart/AddToCartNext`) | **0** | **0** |
| дошёл до оформления `/order` | **0** | **0** |
| `POST /Cart/SendConfirmationCodeNext` | **0** | **0** |
| `POST /Cart/ConfirmAndSaveDelivery` | **0** | **0** |

Реклама ведёт на `https://next.crysshop.kz/`. Источники перехода:
`m.facebook.com` 132, `instagram.com` 88.

Вывод: **обрыв на первом экране.** 97–98% уходят, не долистав главную.
Медиана «жизни» сессии 4 секунды — это время загрузки, дальше запросов от
человека нет вообще.

Проверка вширь: `AddToCartNext` за 07–20.08 — ноль каждый день, кроме 14.08
(6 запросов, это наши тесты при выкате). Шесть дней подряд «В корзину» не
нажал никто.

### Грабля измерения: клики по ссылкам в логах не видны

Next App Router префетчит ссылку, попавшую в область видимости (запрос с
`?_rsc=`), а по клику берёт уже загруженный payload — **сетевого запроса
нет**. На 20.08 из 179 запросов `/basket` 177 оказались префетчем, реальных
заходов — 2.

Что с этим делать:

- `/order` префетчем не тянется (ссылка живёт внутри выпадающей корзины),
  поэтому этот шаг достоверен;
- `AddToCartNext` — обычный POST, достоверен;
- глубина прокрутки считается по числу **разных** префетченных
  `/product/<slug>`: первый экран даёт ровно 3 карточки, больше — значит
  листали.

## 2. Ошибка разбора: кросс-доменная кука

Сначала было решено, что покупку ломает сессионная кука:

```
set-cookie: .AspNetCore.Session=...; path=/; samesite=lax; httponly
```

Фронт на `next.crysshop.kz`, API на `crysshop.kz` — казалось, что `SameSite=Lax`
не пустит куку кросс-доменно.

**Это неверно.** `SameSite` считается по регистрируемому домену (eTLD+1). У
поддомена и апекса он общий — `crysshop.kz`, — значит для браузера это один
сайт, и куку он отправляет. Safari тоже не считает её сторонней.

Проверено настоящим Chromium с эмуляцией iPhone:

```
кнопка «В корзину» найдена: true
запрос AddToCartNext: 200
корзина глазами того же браузера: {"totalCount":1,"totalPrice":1360.00,...}
счётчик в шапке: 1
куки браузера: .AspNetCore.Session@crysshop.kz sameSite=Lax
```

Урок на будущее: «запрос без куки» из curl — не модель браузера. Проверять
такие гипотезы только настоящим браузером.

## 3. Путь покупателя пройден вручную

21.08 весь путь пройден до конца, тестовый заказ создан и затем удалён.

| шаг | результат |
|---|---|
| лендинг | 200, 39,7 КБ, 0,72 с |
| `/Product/GetProducts` | 200, **124 товара** |
| карточка товара | 200, цена и кнопка на месте |
| `POST /Cart/AddToCartNext` | 200, товар в корзине |
| `/order` | 200 |
| `POST /Cart/SendConfirmationCodeNext` | 200, код в WhatsApp дошёл |
| `POST /Cart/ConfirmAndSaveDelivery` | 200, `success: true` |
| в базе | статус **`Confirmed`**, самовывоз, наличные |

Механика магазина исправна от корзины до подтверждения кода.

Полезное про OTP: код шестизначный, живёт в серверной сессии
(`CartController.SendConfirmationCodeNext` → `Session["OrderSmsCode"]`), в
логи не пишется — прочитать можно только на телефоне-получателе. Лимиты
(`OtpRateLimiterService`): 3 попытки ввода → блокировка номера на 24 часа,
5 отправок в час, пауза между отправками 60 секунд.

## 4. Что покупатель видит на самом деле

Лендинг на iPhone 13 (390×664): загрузка 1,3 с, ошибок сети нет, картинки
целы, 124 товара отдаются. И при этом:

1. **В шапке логотип «ShopO»** (`/assets/images/logo-5.svg` — логотип шаблона).
   Человек кликнул рекламу CrysShop и попал на сайт с чужим названием.
   Места: `app/components/Layout/Header/index.tsx` и `Middlebar.tsx`.
2. **Весь первый экран занимает диван Paris за 678 760 ₸** — самый дорогой
   товар каталога. Ни оффера из рекламы, ни поиска, ни строчки о магазине.
3. Страница — 6018 px, девять экранов. Блоки «Новинки» и «Популярные товары»
   (по 24 товара) рендерятся только при прокрутке; первые секунды там пусто.
4. У всех товаров подряд по пять звёзд.

## 5. Аналитики на магазине не было

На `primelegal.kz` стоит полный набор счётчиков: Microsoft Clarity, Yandex
Metrika, GA4, GTM, Meta Pixel. **На магазине был только Meta Pixel**
`356355547516516`, и тот шлёт единственное событие `PageView`.

События `ViewContent`, `AddToCart`, `InitiateCheckout` в коде есть — но в
файле `app/ui/productDetail.tsx`, который **нигде не импортируется**: карточка
рендерится через `app/components/Product/ProductView`, а там вызовов пикселя
нет. То есть Meta знает о посетителе ровно одно — «зашёл на страницу», и
оптимизирует показы под клик, а не под покупку.

### Что сделано в этом коммите

Подключён Microsoft Clarity — записи сессий и карты кликов:

- `app/layout.tsx` — счётчик грузится, только если задан
  `NEXT_PUBLIC_CLARITY_ID`;
- переменная добавлена в `.env.production`, `.env.development`, `.env.example`.

Идентификатор проекта у магазина должен быть **свой**: подставлять сюда
счётчик `primelegal.kz` (`v6vu0lbwj7`) нельзя — смешаются данные двух сайтов.

`NEXT_PUBLIC_*` подставляется на сборке, поэтому после заполнения переменной
нужна **пересборка образа**, рестарта контейнера недостаточно:

```bash
docker compose up -d --build   # бэкенд I-STORE поднимать первым: сеть external
```

## 6. Найдено попутно, не чинилось

- **На проде нет логов приложения.** В `I_STORE.WEB/Program.cs` для Production
  стоит `MinimumLevel.Error()`. Всё, что пишется через `Log.Information`
  (создание заказа, отправка кода, доставка, оплата), не попадает никуда.
- **Продавцу не приходит уведомление о заказе** — Telegram в I-STORE только
  для авторизации, заказ виден лишь тому, кто откроет админку.
- **Дубли покупателей.** `GetOrCreateUserAsync` ищет по точной строке: на один
  номер в базе три записи — `87073816081`, `+77073816081`, `77073816081`.
- **Два разных товара с одинаковым slug**
  `kapronovye-kolgotki-dlya-devochki-…` — `/product/<slug>` открывает
  произвольный из них.
- **Код подтверждения приходит от «Grandaquafarm», +7 778 315 1462** — для
  покупателя CrysShop это незнакомый отправитель.
- Ошибка гидратации React #418 на карточке товара.
- `app/sitemap.ts` строит старые .NET-пути `/Category/Index/<slug>` — все
  адреса в карте сайта ведут на 404 (описано в `server-side-api-direct.md`).

1. Заменить логотип «ShopO» на логотип CrysShop — файла в репозитории нет.
2. Вести рекламу на карточку или категорию из креатива, а не на главную.
3. Первый экран: вместо дивана за 679 тысяч — подборка товаров.
4. Прицепить `ViewContent` / `AddToCart` / `InitiateCheckout` / `Purchase` к
   живым компонентам, чтобы Meta оптимизировала показы под покупателя.
5. Проверить рекламный кабинет за 18.08: 4 посетителя против 47 накануне и 167
   назавтра — это день, когда ловили 525 от Cloudflare.
6. Свести домены на `crysshop.kz` — как гигиену, не как лечение: возврат из
   ForteBank (`hppRedirectUrl`), `metadataBase` и разрешённые хосты картинок
   уже настроены на апекс, и уйдёт OPTIONS-preflight на каждый запрос к API.
