# commorce-front

## Назначение и стек

Витрина и админка интернет-магазина CrysShop (crysshop.kz, админка — next.crysshop.kz/dashboard).
Бэкенд — отдельный репозиторий рядом: `../I_STORE` (ASP.NET Core 8), у него свой `AGENTS.md`.

- Next.js 15 (App Router), React 18, TypeScript; TailwindCSS + тема Sherah (Bootstrap/SCSS) + MUI 5.
- Данные — fetch к бэкенду по `NEXT_PUBLIC_API_URL`; все вызовы собраны в `app/lib/data.ts`.
- Авторизация: WhatsApp OTP и Telegram, JWT в cookie `token`, refresh — httpOnly cookie бэкенда.
- Тесты — Vitest + Testing Library (`*.test.ts(x)` рядом с кодом).

## Структура

- `app/` — страницы App Router: витрина (`shop`, `product`, `basket`, `order`, `payment`, …) и админка `dashboard/`.
- `app/components/` — компоненты витрины (карточка товара, оформление заказа, `Checkout/`).
- `app/lib/` — общая логика: `data.ts` (API), `roles.ts` (роли и разбор JWT), `discount.ts` (скидка),
  `otp.ts`, `CartContext.tsx`, `AuthContext.tsx`.
- `middleware.ts` — пускает в `/dashboard` только роли из `roles.ts`; работает в Edge Runtime.
- `CLAUDE.md` — подробное описание проекта; при расхождении с кодом верить коду.

## Сборка и проверка

```bash
npm ci
npx tsc --noEmit -p .
npm test            # vitest run
npm run build       # долго; нужен для изменений в конфигурации, middleware и роутинге
```

## Правила код-ревью

- **Код общий с бэкендом.** Правило скидки (`app/lib/discount.ts` ↔ `Product.ActiveDiscountPercent`/`PriceAt`),
  длина OTP (`app/lib/otp.ts` ↔ `VerificationCodeGenerator`), набор ролей (`app/lib/roles.ts` ↔ `RolePolicies`)
  продублированы в `../I_STORE`. Изменение с одной стороны без другой — замечание.
- **Деньги считает сервер.** Цена, скидка, доставка и сумма на фронте — только для показа. Не отправлять
  на бэкенд суммы, которым он поверит; проверить, что показанная цена совпадает с той, что посчитает корзина.
- **Доступ.** Скрытый пункт меню или проверка в `middleware.ts` не защищают: `decodeRoleId` не проверяет подпись,
  права проверяет бэкенд. Для новых админских запросов — Bearer-токен и обработка 401/403.
- **XSS.** Проверять `dangerouslySetInnerHTML` (статические страницы из Quill), вставку данных в URL и `href`.
  HTML от пользователя или из базы — только очищенный.
- **Секреты.** В репозитории лежат `.env*` — в них допустимы только публичные `NEXT_PUBLIC_*`.
  Токены, ключи и пароли во фронтенд-код и в эти файлы не попадают: всё с префиксом `NEXT_PUBLIC_` уходит в браузер.
- **Админка.** Отправка формы блокирует кнопку до ответа (иначе двойной клик — дубль товара); ошибка
  показывается пользователю, а не только в `console`. `onError` у картинок обязан снимать `onerror`, иначе
  битая заглушка зацикливается и шлёт запросы без остановки.
- **Серверные и клиентские компоненты.** `"use client"` только там, где нужны состояние или браузерные API;
  в `middleware.ts` и импортируемых им модулях браузерных API быть не должно. Расхождение рендера сервера
  и клиента (время, `Math.random`, `localStorage`) — источник hydration-ошибок.
- **Аналитика.** Pixel/GA/Clarity — через существующие обёртки (`app/lib/fbPixel.ts`); не добавлять чужие
  контейнеры и персональные данные в события.
- **Проверка изменений.** Запускать `tsc` и релевантные тесты; для изменений цены, корзины, оформления и доступа —
  тест на расхождение с бэкендом и на отказ в доступе. Тесты с моками fetch не подтверждают, что бэкенд ответит так же.
